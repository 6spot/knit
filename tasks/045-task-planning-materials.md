# 045 实现任务规划资料与多文件输入生命周期

- 里程碑：首版主会话与规划补齐
- 执行角色：任务资料／领域实现 Agent
- 来源：[044共同契约](044-main-agent-workflow-contract.md)。
- 实际依赖：044的文件职责与变更语义；现有任务文档、输入、冻结、恢复和归档接口。活动运行草案与应用迁移的最终验证依赖029／030，生效指令身份沿用031，不重复修复。
- 唯一状态入口：[TASKS.md](../TASKS.md)。

## 目标与范围

让复杂任务的需求、设计和实施计划成为可持久保存、可交接的任务资料；简单任务继续使用task.md。覆盖创建、读取、更新、冻结、复制／交接、改名定位、恢复和归档，避免只增加模板文件而漏掉业务生命周期。

## 先读

遵守仓库入口与044；按需读取task-document、task-inputs、task-service、snapshot、路径与归档实现，以及009／012／014／016和029–031的验收要求。

## 必需工作

- 实现044约定的任务资料结构、按需创建和引用；创建时不堆空设计／计划／研究文件，现有单文件任务可直接读取与继续。
- 通过统一核心接口读写任务资料，保持CLI与桥接语义一致。任务ID、状态、选择和绑定仍按既有权威保存，不因文件拆分建立第二套状态表。
- 按契约区分有效输入、方案、计划进度与证据；修改进度不无故使需求或检查失效，设计／计划引入新的要求时必须走正确输入更新入口。
- 将多文件修改纳入已有草案和基线核对；活动run继续使用原冻结输入，不能一部分文件已生效、一部分仍为旧版本。复用现有操作与恢复机制，不创建草案队列。
- 冻结与恢复使用实际被采纳的资料版本，能够定位当前计划与未完成步骤；来源不可用时按既有prefer与锁规则处理，不凭Session摘要声称文件已落盘。
- 核对任务路径变化、复制交接、引用失效、缺失／损坏／越界资料和归档后的阅读行为，维持现有路径与凭据保护规则。

## 交付与完成条件

- 单文件旧任务和多文件新任务均可创建、读取、更新、冻结、恢复及归档；无资料丢失或权威重复。
- 验证同一需求下计划勾选／追加证据，以及真正修改目标／条件，两者对摘要和检查资格的影响符合044。
- 验证活动运行期间多文件草案保存、撤回、应用、基线冲突和中断恢复；最终验证必须使用029／030的真实修复产物，替身只证明局部逻辑。
- 验证改名／复制交接后的引用和冻结内容，旧单文件任务无需被强制改写即可继续；执行相称的领域、文件与恢复回归。
- 记录实际修改、测试与未验证项；安装升级的项目模板集成由050完成，不以源码测试代替包内验收。

## 边界

不自动批量迁移当前工程或其它真实项目，不清理用户辅助资料，不让计划中的自由文字直接驱动状态转移。必需依赖未具备时按规则保留未完成验收。

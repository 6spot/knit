# 044 明确主会话工作流与任务规划资料契约

- 里程碑：首版主会话与规划补齐
- 执行角色：设计／契约 Agent
- 来源：用户本轮确认，补齐自然语言任务入口与复杂任务的持久化规划。
- 实际依赖：现有009／010／012／015／022的资料、上下文与桥接接口；可独立于027–043的修复先完成契约，相关缺口只引用原任务。
- 唯一状态入口：[TASKS.md](../TASKS.md)。

## 目标与范围

定义从自然语言需求进入任务、澄清、规划和实施的完整行为，以及小任务单文件、复杂任务多文件的资料职责。将已确认方案写回规范，为045–050提供共同接口；本项交付规范与验收映射，不宣称功能已实现。

## 先读

遵守[AGENTS.md](../AGENTS.md)、[TASKS.md](../TASKS.md)、[BLOCKERS.md](../BLOCKERS.md)。按需读取DESIGN第3、4、7、15、16节，ARCHITECTURE、STATES、OPERATIONS、TECHNOLOGY与RESEARCH中的Trellis参考及固定来源；读取任务文档、输入摘要、上下文规划和桥接实现。

## 必需工作

- 定义普通讨论、非正式小修改、新正式任务、继续已有任务、已有任务补充／范围变化的处理路径；分类由主Agent结合上下文判断，不建立关键词自动建任务规则。
- 明确任务创建／选择授权、用户同意／拒绝／修改提议的后续行为；已有明确授权持续有效，不逐轮重复询问，不将任务授权解释为提交／发布授权。
- 以task.md作为固定入口，定义design.md、plan.md和research/的职责、生成条件、引用与更新方式。小任务可在task.md中完成必要说明；多模块、迁移、协议或跨会话任务等按明确条件持久保存实施计划，涉及重要技术取舍时保留设计依据。
- 明确目标／范围／验收条件、当前方案、实施步骤与依赖、进度和证据分别保存在哪里；各类事实只有一个权威来源，任务身份与业务状态沿用现有机制，不另建task.json权威镜像。
- 区分需求输入、执行方案、上下文引用、观察记录。列明各类修改对输入摘要、检查身份、冻结资料、clarify/change、待应用草案的影响；进度勾选与追加证据不自动成为需求变化，改变目标或验收不能藏在计划记录中。
- 定义讨论完成与ready的结构核对、主Agent的语义判断、待决项处理和实施前核对；不因缺可选文件阻挡简单任务，不从自由正文猜业务phase，不新增独立的规划状态机或强制模型轮次。
- 定义每轮主会话需要的当前任务、phase、待决项、草案／活动运行摘要和下一步规则，区分模型调用前注入、主Agent行为引导和已有副作用守卫；能力以宿主公开API为准，不先假定存在专用对话拦截API。
- 同步相关设计、状态／运行约定、目录示例、命令／工具契约和首版验收章节；替换“执行细步骤仅保存在Session”等过期规则，保留原生Session用于详细执行输出。

## 交付与完成条件

- 规范直接描述当前确认的目标行为，分别标注现有实现、待045–050实现及待051验证的范围；不将规范更新写成已验收事实。
- 提供文件职责／变更影响表、创建到实施的流程与拒绝／变更分支、轻量与复杂任务示例，以及044–051的验收映射。
- 所有会改变授权、摘要或阶段的操作都有明确入口与结果；未决实现问题列出证据和暂定接口，必要取舍按阻塞规则处理。
- 检查受影响引用、术语、默认值及例外的一致性；无需为纯文档修改新增实现镜像测试。

## 边界

不新增Worktree、并行调度、模型运行时或外部插件平台，不将所有任务强制拆成一套空文件。本项不实施后续功能，也不迁移真实项目资料。

# 046 按角色加载任务需求设计与实施计划

- 里程碑：首版主会话与规划补齐
- 执行角色：上下文／快照实现 Agent
- 来源：[044共同契约](044-main-agent-workflow-contract.md)、[045任务资料](045-task-planning-materials.md)。
- 实际依赖：044的资料加载契约、045的读取／引用和版本接口；现有ContextPlan与冻结机制。指令身份与恢复核对使用031的修复产物，不另建身份算法。
- 唯一状态入口：[TASKS.md](../TASKS.md)。

## 目标与范围

使主会话、实施与独立检查实际使用拆分后的任务资料。上下文应支持按需阅读和跨会话接续，不能仅把每个新文件无差别拼接进所有角色输入，也不能把上下文索引当作实施计划。

## 先读

遵守仓库入口及044–045；按需读取context-planner、context-plan契约、snapshot、会话与执行准备实现，现有010／012／013和031的要求。

## 必需工作

- 定义并实现不同角色的最小入口：主会话知道任务与待决项，实施知道确认输入、当前设计、计划与冻结范围，检查知道验收条件、相关方案、实际成果和验证证据。
- 在上下文计划中记录实际选用的资料与适用版本；需求、设计、实施顺序、资料索引各保留自身职责，避免重复复制正文造成多份权威。
- 首轮和恢复均能发现当前计划与未完成步骤；切换任务、更新资料或改变适用规则后重新计算相关内容，不串用另一任务的计划。
- 明确长研究资料的入口摘要与按需读取方式；遗漏必需输入、引用失效或不可安全读取时报告具体缺口，不静默宣称完整，也不自动加载整份研究库。
- 冻结资料与当前任务展示各用其正确版本；进度展示更新不能偷偷替换活动run输入。检查与恢复按031核对实际生效指令。
- 为047提供可消费的主会话上下文结构，为049提供当前规划资料入口，保持CLI与宿主适配之外的核心可测试。

## 交付与完成条件

- 可检查实际ContextPlan和冻结输入，证明多文件资料确实被适当角色使用；文件存在、模型口述“已阅读”不作为唯一证据。
- 覆盖简单任务、复杂任务、无可选文件、长研究资料、无效引用、跨Session恢复与任务切换，验证必要内容完整且没有串任务。
- 覆盖需求更新与进度更新的不同版本效果，指令身份回归与031一致。
- 运行相称的上下文／快照／恢复测试，记录输入构成与限制；真实宿主注入由047、真实对话效果由051验收。

## 边界

不引入Trellis式独立JSONL平台或新的外部插件协议，不扩大到全局知识库。宿主上下文不足时报告能力缺口，不借Pi SDK或自建运行时补齐。

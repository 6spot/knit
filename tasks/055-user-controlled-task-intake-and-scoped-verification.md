## 用户已确认的行为

1. 无论调研还是代码修改，是否创建 Knit 任务由用户决定。用户要求创建就创建，用户明确不创建就直接在会话内执行，不能因代码修改、工作复杂、委派或报告落盘而强制建任务。已有明确选择与持续授权有效，不逐轮重复询问；意图确实不明时才澄清，不能由模型按任务类型替用户决定。
2. 用户只是想了解情况时，可以直接给结论，不强制生成报告或业务任务资料。无任务执行不等于禁用工具或禁止必要的委派，不为委派偷偷创建形式上的任务；同时不把“无需业务任务记录”承诺为“宿主不会保留原生会话或工具记录”。
3. 默认按目标、改动范围、影响和风险执行必要测试／复核，不把某个任务自动升级为全项目全量复核。涉及共享基础设施时可以扩大到有实际影响依据的范围，并说明理由。
4. 用户明确要求的创建方式、验证范围、是否独立复核优先于默认流程；明确未验证项，不把用户要求跳过的验证记为通过。创建任务不附带提交／发布授权。

- 明确默认自检、必要的独立复核及用户显式调整的关系；定义可冻结、可接收的验证要求与完成条件，保证不靠调研／代码标签机械决定。

## 完成条件与验证

- 覆盖调研与代码修改各自的“用户建任务／用户不建任务”，已有授权下不反复询问；普通问答不被强制记录，报告落盘本身不强制升级流程。
- 无任务模式的直接执行及需要委派的入口均有实际实现或明确限制，不能以暗建任务冒充支持。

- 明确任务产物、验证结果和委派回执的归属，验证没有自动提交或额外创建任务的副作用。
- 与 056 联调时能按任务实际要求结束，不因“建立了任务”就强制追加一次独立 check。
- 真机／真实模型验收按用户要求暂缓；执行相称的静态检查和隔离验证，记录真机未验证项，不以替身冒充真实宿主验收。

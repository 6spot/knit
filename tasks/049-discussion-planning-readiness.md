# 049 实现需求澄清持久规划与实施前核对

- 里程碑：首版主会话与规划补齐
- 执行角色：讨论／规划工作流 Agent
- 来源：[044共同契约](044-main-agent-workflow-contract.md)、[045任务资料](045-task-planning-materials.md)、[048任务入口](048-conversation-task-intake.md)。
- 实际依赖：044的轻重任务判定与ready契约、045／046的资料与加载接口、048的需求交接；旧任务可独立进入规划。更新与活动run的最终验证复用029／030等现有修复。
- 唯一状态入口：[TASKS.md](../TASKS.md)。

## 目标与范围

主Agent能在讨论中读代码、识别真正影响实施的问题、保存已确认需求，并形成与任务复杂度相称的设计和实施计划。讨论完成后的结果可跨Session接续，不以模型口头总结或一串泛化步骤代替规划。

## 先读

遵守仓库入口与044–046／048；按需读取讨论指令、workflow、ready与输入更新接口、上下文和执行准备逻辑，核对现有状态与修复次数规则。

## 必需工作

- 从任务资料和相关工程代码取得事实，整理目标、范围、约束、验收条件和影响实施的待决事项；已有资料或授权能够回答的问题不重复询问。
- 只询问确实需要用户取舍的事项，承接多轮回答；用户尚未决定时不能自行选一个方案或以超时当授权，其它独立调查仍可继续。
- 简单任务在task.md形成足够说明；复杂任务持久保存plan.md，重要技术取舍写design.md，必要调查保留research/。实施计划写清步骤产出、真实依赖、受影响结构／接口、验证和风险处理，不照抄编号当依赖。
- 将确认的需求、当前方案、未完成步骤和执行证据保存在各自权威位置；计划与资料入口可供下一Session及实施／检查角色直接使用，详细输出仍由原生Session保存。
- 实施前按044区分核心可核对的结构条件与主Agent的语义判断：缺必需目标／条件／规划或仍有阻碍实施的待决事项时不能宣称ready；不对可选文件一刀切，沿用既有phase与ready入口。
- 实施中补充和范围变化沿clarify/change处理，正确影响输入与检查资格；更新计划进度不重置阶段／修复次数，活动run资料不被静默替换。
- 更新讨论／实施／检查指令的交接要求，使实施实际按当前计划开展，检查按目标和实际成果评价，不凭计划勾选判成功。

## 交付与完成条件

- 覆盖小修复、复杂多模块任务、多轮澄清、未决选择、跨Session继续及实施中变更；检查落盘需求、设计、计划、下一步与实际阶段。
- 验证资料不足时不会直接实施、资料充分时不会无故反复提问；拒绝／未回答不会被解释为授权。
- 验证已知代码事实进入规划，计划步骤与工程结构对应；恢复后保留已完成事实、未完成步骤和待决项，不从头重复或错误宣称完成。
- 验证进度更新与需求改变走不同语义，活动运行继续使用正确冻结输入；执行相称的输入／阶段／恢复与工作流回归。
- 将真实模型行为与确定性接口测试分别记录，完整自然语言验收交给051；缺少真实能力时按事实保留未验收项。

## 边界

不新增独立规划phase、不默认增加模型轮次或强制所有任务走冗长规划；不根据Markdown复选框自动认定业务完成，不绕过既有授权、锁与输入应用规则。

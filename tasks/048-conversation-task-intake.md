# 048 实现自然语言任务识别授权与创建衔接

- 里程碑：首版主会话与规划补齐
- 执行角色：主Agent工作流／桥接 Agent
- 来源：[044共同契约](044-main-agent-workflow-contract.md)、[047主会话注入](047-main-session-context-injection.md)。
- 实际依赖：044的请求分类和授权语义、047的主会话入口、现有任务创建／选择／查询接口；资料写入使用045，展示复用042；可按已明确接口先做隔离验证。
- 唯一状态入口：[TASKS.md](../TASKS.md)。

## 目标与范围

把自然语言请求接到正式任务工作流：识别是否需要任务，必要时提出创建或选择建议，承接用户回答，并把需求保存到正确任务。交付主Agent规则、必要的核心／桥接接口与可验证行为，不停留在“工具已注册”。

## 先读

遵守仓库入口、044／045／047；按需读取workflow、AGENTS与讨论指令模板、任务创建／选择／会话关联实现、042查询展示和相关测试。

## 必需工作

- 实现普通讨论、明确的小修改、新正式需求、已有任务继续和已有任务补充的路径；复杂／跨会话任务引导进入正式任务，日常询问不无故落任务。
- 用户尚未授权创建时，用简洁提议说明目标与拟建任务；处理同意、拒绝、改名、改目标、改用已有任务和延后处理。用户已明确要求建任务或已有持续授权时直接执行，不重复索要确认。
- 通过现有权威接口创建、选择、关联和展示任务；保留稳定身份，避免重试、重复回复或恢复导致重复任务／串绑。创建成功与选择／绑定失败等部分结果须如实呈现并可继续处理。
- 首次需求写入符合045的入口资料，保留已知约束与待决项，随后进入049的澄清／规划；不把尚未澄清的文字直接宣称可实施。
- 用户拒绝创建时不创建任务；仅讨论或未授权实施时不进入实施，用户另行明确要求的非正式小修改按044处理。已有任务补充先识别clarify/change及活动run边界，不默认生成新任务绕过旧任务状态。
- 不将创建授权扩大为提交、推送、发布或真实项目迁移授权；按用户当前指令与既有授权处理必要后续动作。

## 交付与完成条件

- 通过对话序列覆盖显式创建、需询问后同意、拒绝、修改提议、选择已有任务、继续已有任务、重试／恢复与只聊天；核对真实任务记录和当前选择，不只检查回复文案。
- 验证授权持续有效、不同用户回答被正确承接，没有每轮重复询问、重复创建、错误关联或拒绝后副作用。
- 与049之间有明确资料与下一步交接，创建后可定位目标、待决项和当前讨论入口。
- 规则与必要适配同步到源码模板；运行相称的任务／桥接／授权回归。完整真实宿主与自然语言链路由051独立验收。

## 边界

不引入按关键词自动建任务的确定性分类器，不添加一套对话状态库，不自动把开发排程转换成当前工程的产品Task。不能以提示词文本存在替代行为验证。

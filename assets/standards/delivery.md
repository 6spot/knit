## 收尾核对

- 对照任务的完成条件核实实际改动和验证结果再汇报。没运行的验证不写成通过，数字照实际输出写。
- 任务返工过时，汇报返工原因，并问用户是否记入避坑清单。

## 授权与交付

- `knit deliver` 归档任务，并在 Git 仓库里一并提交该任务待提交的改动。交付前须取得用户明确授权，已有授权时不重复确认。
- 一次交付授权同时覆盖后续合并与清理，不含推送、发布和部署。
- 派发过的任务需要补改动时，在任务 Worktree 里改。
- `knit task cancel` 取消任务不可逆，由用户决定。

## 提交文案

- 主会话交付时直接写好文案并提交。首行写明本次改动的结果，不能只有任务编号。
- 由 `knit deliver` 自动追加 `Knit-Task: <id>`，不手写以 `Knit-` 开头的行。

## 异常与红线

- 以输出判断合并和清理结果，不能只看退出码。合并失败或清理被 Git 拒绝时，保留现场，把 Git 的错误原样报给用户。
- 不自行解决冲突，不强行合并，不用 `--force` 删除 Worktree，不用 `git branch -D`。
- 同一操作因同一原因失败两次就停止重试，把命令和错误原样报给用户。

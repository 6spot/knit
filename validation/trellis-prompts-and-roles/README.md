## 术语

- **只读调查／调研**：为回答或评估而读取代码、文档、外部项目，不修改项目、不建立正式任务；不指 Knit 新阶段。
- **正式研究报告**：需要持久化到项目、可独立复核或作为交付物的报告；按正式任务处理。
- **非正式检查**：`knit run check --scope`，只读、不建 Task 绑定、不赋正式交付资格。
- Knit 阶段仍只有 discuss／implement／check／deliver；本报告不引入 research phase。

## 结论速览

1. **真实案例的根因不是模型误读一句提示词。** Knit 的主会话模板没有“较长只读调查／外部项目评估”的显式路径；正式任务又只有 implement 是写入阶段，实施角色固定“完成自检后交独立检查”，核心 `onImplementationAccepted` 再无条件 `implement → check`。任务一建，轨迹就基本确定。
2. **Trellis 的 research 角色不是反例。** 固定基线中，Pi research 角色先解析活动任务，只写当前任务 `research/`；它属于规划阶段的任务内助手，不是免任务、免检查的闭环。Claude 变体在没有活动任务时要求用户指定写入位置，仍不是独立完成路径。
3. **Trellis 的 check 不能照搬。** 它明确“发现问题直接修复”，是自修＋验证；Knit 的检查必须独立、只读、不能修改实施内容。
4. **推荐 A：不新增 research 阶段／角色。** 一次性只读调查放回主会话直接回答；用户明确要求正式跟踪、报告作为成果或独立复核时，才建正式任务，仍走 implement → check → deliver。正式任务默认检查＋受权交付，不提供“免检查／免 Git”的隐式捷径。
5. **需要用户决定的部分已登记。** B006 是正式调研能否跳过检查／免 Git 完成；B007 是 `task close --outcome completed` 目前未核对检查资格的实现缺口。两者都不由本报告自行取舍。

## 真实案例应如何处理

案例事实：`knit-demo` 任务 `k-748f2087202d`（`11-03-eval-pi-rexagents`）只要求静态调研，不安装、不运行、不改项目代码；实际以 implement 派发，接收报告后阶段变为 check。本机没有该项目的可读副本，本报告只使用任务 054 登记的可移植摘要。

在建议规则下：

- **如果用户只要结论**：主会话直接读取／检索并回答；即使临时委派只读子 Agent，也不建 Task、不派 `implement`／`check`。结论和来源随回复交付。
- **如果用户要正式跟踪或可复核报告**：先提议任务，说明将写项目内的报告文件、走独立检查、交付时按授权提交；用户不同意 check／commit 时，不把一次性调查包装成正式任务。
- **如果任务已经被误建**：不要为了满足阶段自动派 check。先与用户确认：
  - 转成正式研究报告：补充报告目标与路径，实施产出报告，再独立检查；
  - 不再需要正式跟踪：按取消／替代结束业务（不是 completed），保留已有记录；归档仍需授权提交。
- **已有正式任务中的辅助调查**：在当前任务内读取或只读委派；需要保留时写任务 `research/`；不新建任务、不自动推进阶段。

## 建议方案摘要

| 请求 | 处理 |
| --- | --- |
| 普通问答、只读代码审阅、外部项目评估 | 主会话直接回答；不建任务、不派 Knit run |
| 非正式小修改 | 当前会话改、自检、汇报；不建任务、不提交 |
| 用户明确要求独立复核、无正式任务 | `knit run check --scope`：只读、不建绑定、不推进阶段 |
| 正式代码／文档开发 | 授权建任务 → discuss → ready → implement → check → deliver |
| 正式研究报告／需要跟踪的调研 | 仅用户明确要求时建任务；报告写项目路径，走 implement → check → 交付 |
| 已有任务的辅助调查 | 复用当前任务；材料可写 `research/`；不推进 phase、不另建任务 |
| 跨会话继续 | 自动恢复选择与注入；不要求手动 `knit start` |

完整分流表、角色职责、文案草案和选项见 [proposal.md](proposal.md)。

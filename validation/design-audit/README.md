# 整体设计一致性审查

审查日期：2026-11-01。范围为根目录九份系统文档：AGENTS、DESIGN、ARCHITECTURE、STATES、TECHNOLOGY、OPERATIONS、GLOSSARY、RESEARCH、WORKTREE。按现行决定核对，不启动产品实现、安装依赖或发送模型请求。

## 现行决定

| 项目 | 当前方案 | 验证／未定边界 |
| --- | --- | --- |
| 产品形态 | 独立 Knit CLI、项目 Pi 薄桥接、本机 local worker | 不建聊天 UI、服务、外部插件平台 |
| Pi 接入 | 本机已安装 CLI，stdin/stdout RPC；宿主公开 API 供薄桥接使用 | 不依赖 Pi SDK／RpcClient，不复制模型／鉴权运行时；已实测版本1.4.0 |
| 恢复 | prefer：优先原生记录，失效后同客户端新 Session 读任务资料续做 | 旧执行未知或模型不可用仍阻塞；不重置任务阶段／次数／scope |
| 原生记录 | 客户端写入；阶段记录跨 run 在稳定位置保留 | opening 可启动模型，只有确认持久化才可称可恢复；原生引用不可恢复不单独触发有效执行重跑 |
| 存储 | Task／规范是 Markdown；run 证据为文件；Session／binding／operation 单一元数据权威 | 原子文件 vs SQLite 仍需M0真实路径比较，不双写镜像，不引ORM |
| 技术版本 | Node24、TS6.0.3、Commander15、TypeBox1.3.27、YAML2.9、node:test | 仍是设计选择；与Pi内部依赖解耦，Node24编译／安装组合尚待实际验收 |
| 首版范围 | 四环节、任务记录、规范演进、独立检查、限定提交归档、查询与恢复 | Worktree、REX、其它客户端、并行调度全部后续 |

## 已修正的遗漏与矛盾

| 编号 | 原问题 | 修正与主要位置 |
| --- | --- | --- |
| A01 | 选用CLI后，TS／Bun取舍仍以Pi内部Node／TypeBox依赖为理由 | TECHNOLOGY改为Knit自身构建选择；Pi为独立进程，不要求同依赖；AGENTS补CLI和禁止SDK的开发约束 |
| A02 | DESIGN列表读取固定文件，WORKTREE绑定固定JSON，与SQLite待定冲突 | 统一经单一元数据仓储读取；ARCHITECTURE补MetadataStore职责，文件端口仍用于正文／证据 |
| A03 | 原生会话放入某次run临时目录，后续恢复又需追加 | 新阶段原生记录由Pi保存到稳定native-sessions/pi；run/native仅放启动／指令资源 |
| A04 | worker被写成原生历史的持久化写入者 | 明确Pi CLI／运行中宿主API写原生记录，worker仅核实引用和结果，不直接追加文件或假造消息 |
| A05 | 拿到Session引用即更新绑定，与available后替换冲突 | opening只登记候选；确认原生ID／归属／持久化后才更新可恢复指针；失败不覆盖旧引用 |
| A06 | 首轮启动条件可能要求空会话已持久化，造成闭环依赖 | 参数／指令就绪即可调用模型，opening不阻首轮；run证据持久化与原生可恢复性分开 |
| A07 | 原生会话跨run追加，却未给旧run划定原生内容范围 | 运行保存起止entry／leaf与增量用量；不可取得如实unknown，不拿当前整Session统计替代旧run |
| A08 | Session锁键只写原生定位，新建无文件时不明，跨项目锁根也未定义 | 本机共享~/.knit/locks；项目按规范化根，Session按客户端／预分配原生身份；项目锁在前，兜底换Session锁且保持项目占用 |
| A09 | 一条CLI命令与prepare/start确认协议的责任方不明 | 明确桥接／直接CLI入口内部保存ID并确认，不是用户二次许可或新增公开命令，丢响应查原ID |
| A10 | 所有JSONL被称为可丢进度，可能误忽略协议尾部／解码错误 | 落盘诊断与传输协议分开；协议增量UTF-8、只按LF切帧；畸形／截断响应不当成功 |
| A11 | 历史只读查询未明确如何避免打开原会话导致写入 | 活跃主会话由宿主API只读取得；离线读已文档化格式，未知只报告引用，不为查询set_model／prompt或打开可写会话 |
| A12 | init ready被等同Pi会自动加载 | ready只指文件与映射；仍遵循Pi原生项目信任，不默认--approve绕过；主桥接与子worker资源策略分开 |
| A13 | 只说明完成消息可唤醒，未定义worker结果如何连接到宿主 | 薄桥接以可销毁5秒定时器只读查询本会话run；校验原上下文／已有通知后投递，切会话／树停止，无新服务或状态库 |
| A14 | 轮外定时回调实验被容易误读为完整产品通知链通过 | TECHNOLOGY增加完整结果连接与宿主工具schema／信任的实际验收，说明个别实验不替代init产物和完整链路 |
| A15 | 已规定需求草案“应用或撤回”，缺操作入口及防旧草案覆盖规则 | task update补apply-pending／withdraw-pending与expect-pending；应用复用kind、核对基线，撤回只留记录，单份草案无新生命周期 |
| A16 | 取消／替代／归档任务可被通用输入变更条款隐式重开；迟到阶段结果缺明确守卫 | 输入更新限定业务范围，关闭先收敛本任务执行／事实并撤回草案；启动／关闭／接收核对版本，旧结果不重开已取消任务 |
| A17 | adopt守卫文字可能被读成允许“有未核实Git效果” | STATES明确无活动／未知run、无未核实Git效果且输入一致才可接管 |
| A18 | 业务摘要与运行模型／Session事实边界不够明确 | 区分需求输入摘要、分支／成果／规则证据与运行事实，主会话换模型本身不使旧检查失效；特定模型验收要求仍按输入处理 |
| A19 | 提示／工具约束容易被理解成任意shell越权都能拦住 | 明确非系统沙箱；阶段核查实际HEAD／index／成果，异常保留事实并needs_attention，不用SDK补隔离承诺 |
| A20 | 部分基本安全规则只出现在M3A行，已有实验又被笼统写成“未验证” | 初始所有权、持久性、来源防误投与关闭竞争放回M0/M1/M2；M3A做健壮性增强；历史stash／后续hook等实验按各自范围表述 |

## 保留而未擅自改变的规则

- 非Git目录可init／context；正式Task创建与代码／交付的Git前置条件已在DESIGN14.1定义，本轮只补状态守卫引用，没有引入nullable分支或自动Git初始化。
- 模型优先级、人工授权、修复轮次、用量只观察、限定提交与不自动改写历史保持。
- 文件／SQLite仍未决定；没有为“统一”而假定数据库已经选定。
- 旧实验报告和参考源码摘录保留原始事实，不将历史文字当作当前规范或为了消除关键词而改写。

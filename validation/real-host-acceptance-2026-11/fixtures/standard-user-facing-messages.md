# 面向用户的错误信息使用英文

**规则**：所有面向用户的错误信息一律用英文表述；中文只出现在日志里。

**依据**：2026-11-04 用户明确提出的长期项目规则（原话：以后面向用户的错误信息一律用英文，中文只放日志）。

**沿革**：本规则**反转**了同日的在先规则「面向用户的错误信息一律用中文，不混英文」。原规则正文见 Git 历史（commit `b733c20` 之前的 `.knit/standards/user-facing-messages.md`）。反转后旧规则失效，不再并列存在。

## 适用范围

- 命令行工具标准输出与标准错误中用户可见的报错、用法提示
- 接口返回的错误消息、校验提示、错误码配套说明
- 界面上的提示、表单校验、通知文案

## 日志中的中文

- 内部日志与诊断输出可以用中文，这是本规则唯一保留中文的位置
- 同一事件同时产生用户消息与日志时，两者语言可以不同，但不得把日志文本直接当作用户消息输出

## 不属于本规则

- 代码注释、提交信息、测试用例名、文档正文
- 标识符：错误码、字段名、API 名、配置键不翻译

## 已知边界（本条落地的推定，与预期不符请指出）

- 第三方库／运行时抛出的原始错误文本：用户消息用英文说明，技术原文可保留在日志中；若用户消息需要引用原文，应放在英文说明之后

## 验证

新增用户可见错误信息时，检查文案为英文；出现中文字符应只落在日志路径上。

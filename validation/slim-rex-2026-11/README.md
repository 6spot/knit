# Rex 窗格：真的 Rex、真的模型走一遍（2026-11-17）

主会话在 Rex 里时，执行者在 Rex 的浮动窗格里跑（任务资料 `.knit/tasks/11-14-slim-refactor/design.md` 第 7.2 节）。自动测试用的是假的 `rex` 和假的 Pi；这里在本机真的 Rex 里用真的模型走一个任务，补上自动测试看不到的两件事：真的模型在窗格里做完一个环节，真的按 Esc 中止之后接着输入。

环境：macOS，Rex 0.1.0-preview.14，Pi 1.5.2，模型 `magpie/group/deepseek`，Node 26.3.0。项目和任务与 H1 的场景一相同（`../slim-h1-2026-11/setup.sh`、`task-body.md`）。

## 结果

两个脚本都以退出码 0 结束，完整输出在 `logs/`。

### 用真的模型走一个任务（`rex-flow.sh`，调用模型两次）

| 看的是什么 | 结果 |
| --- | --- |
| 实现环节在窗格里做完 | 派发后有一个标着 `knit r-f88a671c3328` 的最小化浮动窗格；12.7 秒正常结束，改了 `greet.mjs`、`greet.test.mjs`；`worker.log` 是空的（没有回退）；做完之后窗格自己关掉 |
| 执行者在窗格里跑着时的状态 | `knit run status` 多一行 `窗格: Rex 里标着 knit <执行 id> 的浮动窗格（最小化着）` |
| 审查环节中途按 Esc | 界面上出现扩展的提示；八秒之后 `knit run status` 还是「正在跑」，执行目录里没有 `report.md` 和 `outcome.json`；会话记录里执行者的那条消息结束原因是 `aborted`、内容是空的 |
| 接着输入一句 | 执行者接着做完，结论 `pass`，这次执行一共 37.0 秒；窗格自己关掉 |
| 收尾 | 项目里 `node --test` 2 个通过；没有留下后台进程和等窗格的 `rex wait` |

按键和输入是脚本用 `rex send-key`、`rex send` 发到窗格里的，不是人按的。这个脚本完整通过三次（独立审查之前、按两次审查的意见各改完之后）：实现 10.1、18.5、12.7 秒，审查 21.2、25.6、37.0 秒（含中止之后等的八秒）；表里是最后一次。在这之前手工走通过一次，没有记时长；另有一次脚本自己写错了（见「发现的问题」第二条），停在按 Esc 之后。

### 失败和回退（`no-model.sh`，不调用模型，约 50 秒）

| 情况 | 结果 |
| --- | --- |
| 一、真的 Pi，模型不存在（`magpie/no-such-model`） | 记为「执行者启动失败：Pi 里没有模型 magpie/no-such-model」；执行者是在窗格里开始的，`worker.log` 是空的（没有回退） |
| 二、真的 Pi 在窗格里起不来（provider 不认识，Pi 在加载扩展之前退出） | 回退到后台执行，`worker.log` 是 `Rex 窗格用不了（执行者没有在窗格里开始），改在后台执行`；后台那一次同样启动失败 |
| 三、Pi 在窗格里卡住不开始（一个只会 `sleep` 的假 Pi） | 21 秒之后回退到后台，后台那一次（假 Pi）正常结束；卡住的那个进程被结束了 |
| 四、执行者在窗格里卡着时取消（假 Pi） | `knit run status` 指出是哪个窗格；`knit run cancel` 之后记为「已取消」 |
| 五、派发之后 0、0.15、0.3、0.45 秒取消（假 Pi；前两次取消时执行者还没有在窗格里开始） | 都记为「已取消」；取消返回时工作区里的改动都记下了，返回之后执行者没有再动工作区 |
| 六、执行者在窗格里卡着时用 `session.close_layer` 把窗格关掉（假 Pi） | 记为「执行者的窗格关掉了，没有交报告」 |

每种情况之后都核对了：这个 Rex 会话里的浮动窗格和开始前一样，没有留下后台进程、假 Pi 和等窗格的 `rex wait`。

## 发现的问题

- 派发之后马上取消，窗格里的执行者会留下来接着做：窗格开出来到 Pi 登记之间有零点几秒，取消这时找不到它。第二次独立审查指出，在真的 Rex 里复现了（派发后 0 到 0.45 秒取消，四次都留下一个窗格和一个进程，工作区里多出文件）。已经改了，见 `design.md` 第 7.2 节最后一条；上表第五种情况是改完之后的结果。
- `knit run status <任务> | grep -q …` 会让 `knit` 以 `write EPIPE` 的未处理错误退出：`grep -q` 找到之后就关掉管道，`knit` 还在往里写。和 Rex 无关，窗格之前就有；这次没有改，脚本里改成先把输出存进变量。

## 没有验证的

- 人在窗格里直接操作：把最小化的窗格点开、用键盘按 Esc 和输入。
- 中止之后一直不输入：这次执行会一直算正在跑，只看了八秒。
- 窗格里的执行者交了读不出来的报告之后补报：只有自动测试（假 Pi）。
- 主会话经桥接（`knit_run`）派发到窗格：这里用的是命令行；桥接只是转交同一条命令。
- Linux 上的 Rex；别的模型。

## 怎么重跑

```bash
npm run -s build                       # 演练进行时不要再运行它
validation/slim-rex-2026-11/no-model.sh
validation/slim-rex-2026-11/rex-flow.sh
```

要在 Rex 的终端里运行。`rex-flow.sh` 还要本机有 Pi 和 `magpie/group/deepseek`，会调用模型两次。

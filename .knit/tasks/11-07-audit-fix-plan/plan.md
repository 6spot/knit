## 1. 根因与修复原则

| 根因 | 体现 | 修复原则 |

| R1 成果认定不完整 | F1：阶段内提交、ignored 文件、`.git`、`.runtime` 都看不见；HEAD 和 index 没有冻结 | 阶段前冻结 HEAD、index 与工作区签名；敏感区单独核对；看不见的部分如实报告 |

## 5. 回归场景（每条都写成自动化测试；总任务收尾时在隔离夹具中复跑一遍）

1. 阶段内 `git commit` → `head_moved_during_stage`。
2. 阶段写 `.git/hooks/pre-commit`、`.knit/.runtime/checks/x.json` → `protected_runtime_modified`；写 `node_modules/` → `ignoredChanges` 有记录。
3. run 期间用户写入、Agent 未列 → 进 `externalChanges`，不进产物提交；Agent 列出但非工具写入 → `unattributed_paths`。
4. 失败 run 留下文件，下一轮声明继承 → 接收成功。
5. `[read, exec]` 检查阶段写文件 → `write_without_capability`；允许写的检查阶段修复后 pass → 凭据与提交如实标注。
6. 空 scope 的 self 任务 close → `empty_scope`。
7. 杀掉 worker → 下一条命令自动回收锁；`resume` 后新 run 真实执行并接收。
8. auto 模式下 Rex 未报到 → 回退 local。
9. clone 后 → `task rebind` → 可完成。
10. 篡改凭据 → `credential_tampered`；worker 环境中调用 `deliver` → `stage_context_forbidden`；交付时不执行植入的 hook。
11. 用户编辑 `task.md` 输入区 → `stale_input`（不是 `protected_path_modified`）；run 期间可以 `task new`。
12. `tools: []` → `--no-tools`；`tools: all` 或不写 → 全部放开。

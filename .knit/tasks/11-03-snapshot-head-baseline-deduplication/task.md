# 快照：HEAD 基线引用与内容去重

## 目标与边界

实现当前运行约定明确留待后续的 HEAD 快照策略：与基线相同的内容可引用可核实 Git 基线，仍完整保存需要恢复的差异。

这是用户要求盘点并拆分的设计后续能力，属于后续规划。本轮仅登记任务和边界，保持 open／discuss；不开始技术实施，不调用模型、Rex 或真实项目操作，不改变首版范围。具体方案和完成条件按下述设计来源及待验证事项继续澄清，不把规划建议或尚未核查的能力当作事实。

### 本任务的交付范围

- 核查当前全量快照、index、未跟踪文件、权限／类型及逐路径恢复契约，设计必要的基线引用和兼容读取。
- 保留冻结前后核对、完整性和大小限制语义；不以隐式 stash 改写用户工作区或 index。
- 本任务不顺带开启自动 GC；基线引用的创建、保存和后续回收约束要清楚。

以下是依据现行设计拟定的可验证交付方向；Planner 在实施前对照真实方案复核，范围变化按 Knit 输入更新规则处理。本轮没有执行这些验收。

- 旧全量快照可读，恢复不丢信息且仍核对 expect；真实可恢复性和节省量可说明，不凭理论推断。

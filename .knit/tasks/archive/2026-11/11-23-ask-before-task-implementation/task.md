## 目标与范围

修复一个可复现的漏问。主会话在没有选中 Knit 任务时收到用户对实施范围的肯定，随即派发子 Agent 并改动仓库，跳过了应由用户决定的“这项工作要不要建任务”。预期在第一次实施性委派或工程改动之前，就能看出用户对建任务的选择。

- 统一仓库协作说明、讨论规范和主会话无任务提示。Pi 的每轮提示、`knit_task` 工具说明，以及 Antigravity 和 WorkBuddy 共用的会话入口，应给出相同的判断和下一步。源文件按执行时的规范加载方式定位。不要直接改安装版和 `init` 生成的副本，避免下次安装覆盖修复。
- 写明何时重新判断。答疑、比较方案和为判断范围而只读查证可以直接进行。用户已授权实施的单点小改，只要无需委派，就直接处理，免问是否建任务。准备实施或原本的小改扩大时，按已有的委派条件判断，包括跨模块、多文件、需要独立审查和用户指定委派。命中任何一类且用户尚未表态，就说明本次命中哪一类，直接询问是否建任务，等待答复。无关的已选任务不能代替这次选择。
- 写明同意的是哪件事。本案里对“要按这个范围落实吗”的“可以”只回答实施范围。可直接接着问“这次会改到规范加载、初始化和执行者交接，要为它建一个 Knit 任务吗？”用户已明确要求建任务时沿用该答复，创建草稿；明确选择本次不建时沿用该决定，按已授权范围走宿主流程。如仅同意建草稿，完成草稿就停在 `draft`。
- 把必问条件和用户选择落实到能观察的会话行为。用测试宿主复现模型跳过提问、直接请求实施性委派或写入的路径，核对实际调用、仓库内容及任务记录。覆盖普通编辑工具和通过宿主命令改文件的典型入口。单查提示词里有没有某句话，无法证明工具调用会被拦下。若某宿主缺少执行前控制能力，独立审查应标出具体入口和阻塞，不能据此报告所有宿主已防住漏问。
- 本次交回修复与回归证据。前次规范迁移的代码、提交文案文件的取舍、全局安装和真实模型调用都不属于本次实现。

## 完成条件

### Requirement: 主会话在实施前取得用户对建任务的选择

#### Scenario: 自由讨论转为跨模块实施，用户只回答了实施问题

- GIVEN 无相关已选任务，先回放“有必要合并吗”的讨论，再回放复盘中的实施问题和“可以，记得我们系统内置的规范……”的原话
- WHEN 主会话首次准备委派实现或写入仓库，包括把具体改动直接交给宿主工具
- THEN 纯讨论和只读查证正常；用户先看到针对本次工作的建任务询问，回答前没有创建草稿、实施性委派或工程文件改动。绕过提问的调用要用实际结果核实

#### Scenario: 用户已经明确决定是否建任务

- GIVEN 同一范围内分别回放“建一个修复任务”和“不建任务，按刚才说的改”
- WHEN 主会话处理答复或继续该工作
- THEN 前者创建唯一一份 `draft`，回报标题、编号、链接和选中状态；后者按此前授权直接工作。两者都无需反复询问，仅同意建草稿时不会进入实施

#### Scenario: 单点小改直接处理，范围扩大或会话恢复时重新判断

- GIVEN 用户已授权处理一个无需委派的单点小改，或者恢复会话后收到“继续”
- WHEN 分别回放小改保持原范围、小改经查证需要跨模块实施，以及恢复会话后继续工作的情况
- THEN 在各支持宿主的正常入口，保持原范围的小改直接完成，建任务询问次数为零。范围扩大或会话恢复后，沿用用户对本次工作的决定。如果用户尚未表态且已达到必问条件，在下一次实施性委派或写入前询问并等待答复。独立审查用实际输出及副作用核对结果，列明覆盖的入口与剩余缺口

## 结果

Pi、Antigravity 和 WorkBuddy 的主会话在首次实施性委派、普通编辑或命令写入前按本次授权范围判断是否要询问建任务。已获授权且无需委派的单点小改直接处理。需要委派且用户只确认了实施范围时，说明原因，询问是否建任务并等待答复。明确建任务只创建一份草稿，仅同意草稿时停在 draft。明确不建时可继续实施，补充细节或恢复同一工作沿用原选择。

独立审查 r-35bff25d4f51 通过三个完成场景。36/36 组对照核对了实际工具调用、文件内容和任务记录。项目全量替换命中一个文件时直接修改，命中三个时答复前写入为零。用户只授权改项目简介时，即使搜索命中三个文件也只改 README。两轮返工修正了澄清与新工作的区分、草稿授权和多文件范围判断。

Rex 和普通 Terminal.app 各运行 npm test，均为 583 项、576 通过、0 失败、7 项因缺少第二个可写文件系统跳过。84 项任务回归全部通过。源码与模板类型检查、pack:check 和 git diff --check 通过。

首问验证到宿主协议。Pi 发出可显示消息，WorkBuddy 返回 systemMessage，Antigravity 的 PreToolUse 把问句放在拒绝原因中，真实界面是否主动显示仍待验证。本轮未运行真实模型或升级全局安装版。

## 目标与范围

现在整个项目同一时间只能跑一个执行者：有一个任务在跑时，派发别的任务会被拒绝。原来这样规定是因为执行者都在主检出里写，改动分不清是谁的。现在每个任务在自己的 Worktree 里执行，改动对比和受保护文件的检查都只看那个 Worktree，这个限制不再需要。

做完之后：「项目里只能有一个执行者」改成「一个任务同一时间只有一个执行者」。不同的任务可以同时派发，各自结束，各自给主会话发一条通知。

规则：

- 派发时只检查这个任务自己有没有还没结束的执行；别的任务在跑不拦。
- 同一个任务已经有执行在跑时照旧拒绝，提示不变。
- 同时跑几个不设上限。
- 各任务写的是自己的 `task.md` 和 `record.json`，运行资料在各自的执行目录里；写任务文件时核对版本的做法不变。
- `knit run status`、`knit run wait`、`knit run cancel` 本来就按任务工作，行为不变：取消一个任务的执行不影响别的任务。
- 桥接按任务等执行结束，本来就能同时等几个；确认两个任务同时在跑时各收到一条通知，缺测试就补上。

要查的地方：仓库里凡是按「项目里最多一个执行在跑」写的代码和说明都要找出来改掉，包括 `docs/design/DESIGN.md` 第 7 节（「整个项目同一时间仍然只跑一个执行者」）和第 11 节（「Worktree 并行」那一行延后的功能、「锁子系统」那一行里「改为一次一个执行者」的说法）。查到有共用的运行资料（几个执行会写同一个文件）时，改成各写各的；改不了时停下来报告。

不加的东西：

- 不加锁，不加排队和调度：会改同一批文件的任务由拆分规范用 `dependsOn` 排先后，合并时的冲突由交付处理。
- 不改依赖的规则：依赖的任务 `done` 就可以派发，这一条在下一个子任务里收紧。

不能变的行为（都有测试）：

- 一个任务的改动只记它自己 Worktree 里的；执行者不能提交、不能改受保护文件的检查不变。
- 只跑一个任务时，所有命令的输出与现在逐字相同。

不能动的：

- `.knit/standards/`、`.knit/workflow.yaml`、`.knit/config.json`、`.knit/agents/`、`.pi/extensions/knit.ts` 是受保护的或者是生成的副本，改了这次执行会记为失败。
- 交付的代码（`src/application/delivery.ts`、`src/cli/deliver.ts`、`src/infrastructure/directory.ts`）。
- `validation/`、`docs/history/`、`docs/research/` 是历史记录，不改。不加依赖。

环境：

- 这个任务在它自己的 Worktree 里执行。`node_modules` 不在时先运行 `npm ci`；装不上时停下来报告。
- 主检出只读，不要在里面改任何东西。
- 测试用仓库里已有的假 Pi（`test/helpers/fake-pi.mjs`），它能等一个文件出现再结束，可以让两个执行同时在跑。测试辅助已经把 `KNIT_HOME` 指到临时目录。

验证：

- 新的场景先写测试，看到它失败再改代码。
- `npm test` 全部通过，测试个数不比改之前少（改之前先运行一次记下个数；改之前就有失败时停下来报告）；`npm run typecheck` 退出码 0。平时有 7 条跨文件系统的交付测试是跳过的，属于正常。
- 运行前后各看一次 `git worktree list`，应当只有主检出和这个任务自己的 Worktree；测试结束之后没有留下还在跑的假 Pi 进程。

交回：不提交。做完之后改动留在 Worktree 里，由主会话核对，用 `knit deliver` 交付。

## 完成条件

### Requirement: 不同任务可以同时执行

#### Scenario: 一个任务在跑时派发另一个任务

- GIVEN 任务甲的执行者还在跑
- WHEN 派发任务乙
- THEN 派发成功，两个执行者各在自己的 Worktree 里
- AND 两个都结束之后，各自记下的改动文件只有自己改的那些，各自的状态都推进了

#### Scenario: 同一个任务不能同时跑两个执行者

- GIVEN 任务甲的执行者还在跑
- WHEN 再派发任务甲
- THEN 派发被拒绝，提示这个任务的执行还没有结束，没有新的执行记录

#### Scenario: 取消一个任务的执行不影响另一个

- GIVEN 任务甲和任务乙的执行者都在跑
- WHEN 取消任务甲的执行
- THEN 任务甲的这次执行记为失败，它的进程不在了
- AND 任务乙的执行者继续跑，之后正常结束

## 结果

做成了：派发时只检查这个任务自己有没有还没结束的执行，别的任务在跑不再拦；同一个任务已经有执行在跑时照旧拒绝，提示逐字不变。不设并发上限，没有加锁、排队或调度。代码只改了 `src/application/run-prepare.ts`（去掉扫全项目找未结束执行的函数，改成只看本任务的记录）和 `src/cli/run.ts` 的一句注释；运行资料本来就按执行 id 分目录，没有共用的文件。`docs/design/DESIGN.md` 第 7 节、第 11 节和 `docs/README.md` 里按「全项目只有一个执行者」写的说法都改了。依赖的规则、取消的逻辑、交付的代码没动。

三个完成条件都有测试并通过（用假 Pi）：甲在跑时派发乙成功，两个执行者各在自己的 Worktree 里，结束后各自只记自己的改动、状态各自推进；甲在跑时再派发甲被拒绝，没有新的执行记录；取消甲之后甲记为失败、进程不在了，乙继续跑并正常结束。另外补了桥接的测试：两个任务同时跑时各收到一条通知。

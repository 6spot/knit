# Worker 派发标准：规则、落地与验证

状态：标准已定稿（2026-11-06），未实施。本文件只记录方案，不改代码。

## 1. 标准正文（写入提示词与文档的定稿措辞）

**判断顺序**

1. 先判断「可委派」：需求稳定、目标与验收写得清、执行期间不需要频繁反问主会话、不依赖主会话未落盘的判断。不满足则留在主会话（先澄清或边做边确认），不派 worker。
2. 可委派时，满足任一条件派 Knit worker：
   - **W1 独立检查**：任务要求 `independent`，或正确性无法由作者自证（协议、数据迁移、权限、并发、安全、`.knit/` 等保护路径）。
   - **W2 改动面**：点名后能看到 ≥ 3 个文件，或跨 ≥ 2 个模块／包（含必须同步的配置、测试、文档）。
   - **W3 摸底成本**：动手前要读 ≥ 8 个文件或 ≥ 1500 行，或依赖大量搜索／长日志。
   - **W4 用户指定**：用户明确要求走 worker 流程。
3. 否则主会话直接做：单文件或纯文案／注释／小函数／单个配置项；已知道改哪；自证足够；一次做完。

**不使用**：墙钟时长、步骤数量、阶段数量作为阈值。动手前无法可靠预估耗时；阶段数由 `.knit/workflow.yaml` 决定（本项目当前是 implement／check 两个），不能当通用判据。

**恢复不属于判据**：中断恢复、跨会话接续是正式任务的共同能力（任务绑定、记录区、阶段 Session），主会话与 worker 都能续，且动手前无法预知是否会被打断。需要跨会话时靠建任务留档，与派不派 worker 无关（原 W4 已删除）。

**硬约束**：Knit 正式 run 必须绑定任务（`run prepare/start/implement/check` 都要 `--task`）；无任务时的复杂工作使用宿主通用子 Agent 或主会话，`run check --scope` 只作非正式只读核对。是否建任务由用户决定，Agent 只提议，不代建；标准说「该派 worker 但没有任务」时，先向用户提议建任务。

**不新增记录**：交付报告不标明执行方式；`task implement` 与 run 目录已能事后核对。

## 3. 与既有机制的关系

- **任务创建**：不变，由用户决定；标准只影响「谁来实施」，不影响「是否建任务」。Agent 不可自行建任务来满足 W1。
- **`task implement`**：保留为正式任务内主会话实施的记录通道，适用于未命中 W1–W4 的收尾性改动；不得用它绕开 W1 要求的独立检查。
- **`verification=independent`**：必须走正式检查，即必须有任务并派 `run check`；不能以主会话自检或 `run check --scope` 冒充。
- **无任务委派**：宿主通用子 Agent 不属于 Knit run，不写任务 scope，不产生完成凭据；交付与追溯仍按无任务处理。
- **`run check --scope`**：非正式只读核对，不赋交付资格，不替代 W1 的正式检查。

## 4. 反模式（提示词里点名）

- 一行文案、单文件小改也派 worker（Cline 明确称为 unnecessary overhead）。
- 跨多个文件／模块的重构由主会话硬做，超出上下文后靠压缩续命。
- 用 `task implement` 给 W1 类工作收尾，跳过独立检查。
- 没有任务却擅自建任务以便派 worker。
- 静默降级：worker 起不来或没有任务时，假装已按流程执行。

## 5. 测试与验收

机械验证（可做）：

- 受管块、两个桥接文件、初始化模板输出包含 W1–W4 关键句且逐字一致（沿用 `test/init.test.mjs`、`test/bridge-query.test.mjs` 的一致性断言方式）。
- `agentsManagedBlock` 输出与仓库 AGENTS.md 受管块一致。
- 文档同步：DESIGN §4.2 与 ROLE-CONTRACT 新增段落存在且与提示词口径一致。

行为验收（另记，不冒充已验证）：

- 真实会话中：小改动不派 worker；跨模块改动派 worker；无任务时复杂工作走宿主子 Agent；`independent` 任务不被主会话自检替代。用户已把真实宿主验收延期。

## 6. 风险与边界

- 阈值是判断辅助，不是审批门槛；用户可用 W4 覆盖，也可明确要求主会话做。
- 主会话可能倾向「自己做更快」，导致 W1–W3 命中仍不派；提示词点名反模式，但不做机械拦截（无法从上下文可靠判定复杂度）。
- 不做新的 run 模式，不让 run 脱离任务；若以后要「无任务 worker」，需要单独立项重新定义身份、scope 与完成凭据。

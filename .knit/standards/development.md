## 范围

- 实现范围以任务和它点名的设计为准。范围外的功能不做，发现的问题写进报告。
- 动手前先找出受影响的字段、命令、配置、引用和测试，一起改；只读当前任务需要的资料。
- 改名称或路径时，沿创建、传递、列出、归档整条链路核对。可读名称、稳定身份和实际位置是三样东西，不混用。
- 只持久化必要的事实；观察到的值和内存里的资源不做成独立的状态机。
- 执行者通过本机的 Pi 命令行和它公开的输入输出协议启动；不引入 Pi SDK，不另建模型或鉴权运行时。缺少能力时先报告。

## 复杂度

- 问题能直接实现就直接实现，不做防御性的过度设计。
- 为极不可能发生的竞态或安全场景增加复杂度之前，先向用户说明会出什么故障、多大概率、要多少成本，得到同意再做。
- 逻辑留在一个函数里，除非拆出的部分可组合或会被重用。
- 不预先提取只用一次的辅助函数；只有会重用、藏着真正复杂的边界，或名字能让调用处更好读时才提取。
- 函数有多个校验分支时，主函数读起来是正常路径，细节放进紧跟其后的小函数。
- 未知的值在拥有它的边界上校验一次，往里传有类型的值，不重复校验。
- 默认在既有同主题文件内扩展，不为单次增量或单个小函数新建文件。
- 新建文件须满足至少一条：独立外部入口或延迟加载边界、跨 3 处以上复用的共享契约或基础原语、高风险独立审查边界（状态推进、快照保护、结算、交付），或原文件超过约 350 行且存在清晰内聚的子域。
- 不创建无逻辑增量的空壳重导出文件（barrel）或仅被单个调用方使用的不足 60 行碎片文件。
- 跨层或跨适配器共享的底层原语（文件锁、环境变量清理、进程与文件工具）下沉到 `infrastructure/`，不反向依赖 `application/`，也不跨适配器互导。

## 写法

以下只约束新写的代码，不要求回头整理现有代码。

- 尽量不用 `try`／`catch`。
- 不用 `any`。
- 靠类型推断；只有导出或有助理解时才写显式类型。
- 用 `const`，不用 `let`；用三元表达式或提前返回代替重新赋值。
- 不写 `else`，提前返回。
- 只用一次的值直接内联，不为它起变量。
- 不做不必要的解构，用点号访问保留上下文。
- 数组处理优先用 `map`、`filter`、`flatMap`，而不是 `for` 循环。
- 导入不起别名，不用 `import * as`，不在类型位置写 `import("…")`。
- 只在少数路径用到的重模块用动态导入。
- 注释只写不明显的约束和出人意料的行为。

## 测试

- 每次改动跑哪些测试，按 `AGENTS.md`「本仓库开发与验证」里的范围定。
- 按副作用和不变量选测试，只保留必要的；只读的操作不套崩溃场景。
- 验证是为了查出会改变结论的问题。代码和输入都没有变时，已有的结果直接用，不为了安心重跑。
- 测真实实现，不在测试里重写一遍被测逻辑；尽量不用 mock。
- 涉及 Git、模型和故障的测试在隔离的临时夹具里做，不提交当前工作区，不改写历史。
- 测试按主题文件组织，新场景优先追加到对应主题的既有测试文件，不按任务编号或单个子功能新建 `*.test.mjs`。
- 遵循测试分层：纯解析、校验、规则与状态机矩阵（尤其是多参数组合）直接内存调用 `domain/` 或 `application/` 函数；CLI 与宿主钩子层只保留少量端到端冒烟（入口参数、退出码、输出格式、权限与钩子封包），不在 CLI 子进程里重复遍历纯逻辑分支。
- 测试夹具优先通过应用层函数与只读模板仓库复制构造，不在夹具准备阶段反复启动 `knit` CLI 或重复 `git init`。
- 新增或改动的单个测试文件耗时原则上控制在 5 秒内；需要等待异步进程的测试优先使用短轮询间隔或测试注入宽限期，不引入无意义的整秒 `sleep`。

## 文档

- 改完通读相关章节，核对规则与示例、默认值与异常处理是否一致。
- 搜索旧名称、旧路径和被替换掉的说法。
- 核对章节编号、交叉引用和 Markdown 结构。
- 只整理文风时不改变既定行为、授权边界和数据含义；需要改设计时单独说明。

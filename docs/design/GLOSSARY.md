# Knit 术语

首版范围见 [DESIGN.md](DESIGN.md#151-首版闭环)，运行约定见 [OPERATIONS.md](OPERATIONS.md)，枚举与转移见 [STATES.md](STATES.md)。

| 术语 | 含义 |
| --- | --- |
| 主会话 | 用户与主 Agent 沟通的原生客户端会话；首版为 Pi 主会话 |
| 主 Agent | 主会话中的模型执行者，负责沟通、协调、结果整理与调用 Knit 工具 |
| 子会话／阶段 Session | 为某个阶段创建或恢复的独立原生会话，实施和检查分别保存引用 |
| Knit Session | Knit 索引中的稳定身份，记录客户端、任务、父子关系与原生定位，不保存一份替代原生历史的对话副本 |
| 原生 Session | 客户端自己保存的对话、工具记录与会话格式；阶段记录跨 run 保留，索引与原生文件分开，读取不改写原记录 |
| run | 一次 worker 执行尝试，恢复也产生新 ID；主 Agent 直接讨论／收尾写操作事实，不伪造 worker run |
| 状态契约 | STATES.md 中的对象、事件、守卫与恢复规则；持久状态和派生观察分别处理 |
| 操作 operation | 带稳定 ID 的确定性效果意图、步骤与核验回执；副作用未知先核实，不能盲目重做 |
| worker | 执行阶段请求的本机进程，按需加载所选 AgentRuntime；进程结束后原生 Session 和 run 资料可继续保留 |
| ClientAdapter | 内部模块，生成项目入口与桥接，启动客户端并取得真实主会话上下文 |
| AgentRuntime | 内部模块，负责阶段 Agent 执行、取消、历史与恢复；首版调用本机 Pi CLI，旧记录无法恢复时同客户端新会话读任务资料续做 |
| ExecutionHost | 内部模块，启动和定位 worker；首版 local，REX 后续 |
| 项目桥接 | init 生成的客户端集成文件，Pi 为 `.pi/extensions/knit.ts`；转交原生上下文并轻量观察本会话 run，业务由 CLI 处理，不另建常驻服务 |
| 可插拔模块 | 随 Knit 源码维护和构建的内部实现，通过固定装配表替换，不是第三方插件 SDK |
| 阶段／phase | 进行中任务下一步所需的四环节；取消／替代时保留停止位置，由 frontmatter 保存 |
| 业务结束／closed | 业务不再推进；收尾是否完成另看真实提交、归档和操作回执 |
| 父任务／子任务 | 以稳定任务 ID 记录的层级关系，只存子任务 frontmatter.parent；父任务总体验收需子任务全部结束并由主会话给出依据，父子不等于执行依赖 |
| 优先级 | 任务自身 P0–P3 的业务排序权重，缺省 P2；与父子层级和阶段状态无关 |
| 前置依赖 | dependsOn 记录的稳定任务 ID 列表；启动实施前必须全部完成，不可由优先级或用户指定绕过 |
| 业务执行顺序 | 由优先级、同优先级内的人工 order 与真实 createdAt 派生的稳定顺序；人工调整只在组内生效，不改写原始创建时间 |
| 任务选择快照 | 索引 selectedTaskId 反映已核实的原生有效路径关联事件，树切换后重新推导 |
| 绑定 | 本机任务到项目、分支、run／Session 的关联；分支接管不等于重做需求讨论 |
| 有效输入／记录 | 输入定义目标、条件和适用规则；进度、经过、验证结果、运行引用属于记录，不改变业务摘要 |
| 任务规划资料 | 复杂任务按需创建的 plan.md（实施计划与未完成步骤）、design.md（技术取舍依据）、research/（调查材料）；task.md 仍是业务状态唯一权威，进度勾选不改变需求 |
| 输入确认 | task ready 保存已确认目标、条件与资料；人工验收按用户要求由主 Agent 核对，不设独立门槛命令 |
| 成果范围 scope | 核心确认的任务成果路径与版本；检查对该范围成立，不从模型摘要猜全部改动 |
| 封存 seal | 收尾短锁内固定的任务记录及目录版本；之后补记另行处理，不伪称已入本次提交 |
| 收尾辅助 | advisory worker 提供建议；只有主 Agent 与确定性工具的实际结果能证明提交和归档 |
| 用量 | 本 run 新模型调用的 token／费用／耗时统计，缓存是输入子集；首版不作为自动停止阈值 |
| 检查凭据 | 核心在结果接收时写入 `.runtime/checks/<run-id>.json`，发布后不改；只取最新候选并核对当前目标；stale 不删除旧事实 |
| clarify / change | 澄清保持早期 phase；摘要变化令检查 stale，deliver 因此回 open/check；实变回 discuss |
| 自动修复计数 | binding 中的 repairCycleId、repairRounds、stopReason；恢复与 clarify 不重置，不做独立链状态机 |
| 开发者模式 | M1 仅 --dev 的脱敏结构化 stderr；M3A 加私有日志和 Pi 会话开关，不改规则或自动多调模型 |
| 提交确认与来源 | --branch 明确完整目标，authorizationRef 追溯指令或认可策略；核心核引用／版本，主 Agent 判断授权语义 |
| Git 分支 | 项目版本控制分支；首版任务随其所在 Git 分支保存 |
| 会话分支／对话树 | 原生 Session 的消息路径，与 Git 分支分别处理 |
| 快照 | 实施前的本机文件与索引恢复对照，不等于 Git 工作提交或外部副作用回滚 |
| Worktree | 后续独立执行目录能力，首版不实现 |

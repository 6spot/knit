# 052 核对Pi 1.5.0公开接口并完成兼容与能力采用评估

- 里程碑：首版运行时兼容
- 执行角色：Pi CLI／宿主适配 Agent
- 来源：用户要求兼容最新版Pi，阅读更新日志，核对CLI公开能力变化及值得采用的能力；本轮明确目标为1.5.0。
- 实际依赖：现有003／005的CLI与宿主探针、Pi适配器和桥接源模板、TECHNOLOGY中的支持约定。可独立核对和修复现有基线，不以027–051全部完成为前置；044–050尚未实现的能力先交接精确接口约束，最终集成由050／051核实。
- 唯一状态入口：[TASKS.md](../TASKS.md)。

## 目标与范围

按实际版本、公开文档与运行证据确认Knit对Pi 1.5.0的兼容性，修复必需适配，并判断哪些新能力有助于现有CLI阶段执行、主会话桥接、任务询问和恢复。区分破坏性变更、已有行为修复、新可选能力和无关变更；不能只改版本号或根据日志宣称兼容。

## 先读

遵守[AGENTS.md](../../../AGENTS.md)、[TASKS.md](../TASKS.md)、[BLOCKERS.md](../BLOCKERS.md)。按需读取TECHNOLOGY、ARCHITECTURE、OPERATIONS与003／005及相关验证目录，检查src/adapters/pi、阶段执行、用量解析、桥接模板、初始化和打包实现，结合044–051的目标接口。

从实际安装包读取package.json、CHANGELOG和相关公开CLI／RPC／Extension／Session文档，使用pi --version和pi --help记录实际暴露的能力；核对[官方项目](https://github.com/earendil-works/pi)和[官方文档](https://pi.dev/)的版本来源。实施宿主变更前完整阅读对应文档与示例。留存可移植的版本／来源和必要摘录，不能只留下本机绝对路径或会变化的latest链接。

## 已知核对线索

以下来自本轮读取的1.5.0更新日志，只作为调查入口，不代表已经证明影响Knit或决定采用：

- 工具参数校验改为pi-schema；普通JSON Schema也有类型转换，错误消息变化。核对工具schema、默认值、缺失／额外／错误类型字段、调用后实际值，以及TypeBox兼容导入；非法参数不得穿透核心写边界。
- pi.exec()新增maxBuffer与truncated，超量输出会终止命令，超时／取消的SIGKILL补偿得到修复；核对桥接当前执行方式是否涉及该接口，以及与Knit进程组和取消回执的边界。
- 已保存“不信任”判定、会话写入／恢复、bash取消、工具检索和动态工具集相关修复，可能影响现有准入或新主会话入口，须按真实使用路径确认。
- inline ctx.ui.custom()新增blocked；Usage.cost.totalFromProvider区分提供方账单与估算，responseModel提供实际响应模型信息。分别评估对任务询问、用量与诊断是否有价值，不以新字段存在为采用理由。
- 模型目录／默认模型、系统提示和扩展加载行为有变化；核对显式配置、工具可见性与包内模板，不让宿主默认变化静默改变Knit的模型或业务规则。

## 必需工作

- 对比仓库已验证的精确Pi基线与1.5.0，阅读跨越版本的破坏性变化和相关修复；若基线并非1.4.0，不只阅读1.5.0这一节。执行时核实官方稳定版本并记录目标，不能用模糊“最新版”覆盖版本证据。
- 建立“变化／来源与版本／实际使用点／业务影响／处理决定／验证证据”表。对于公开文档中早已存在的接口，明确它不是1.5.0新增；标清哪些只是宿主修复、无需Knit改代码。
- 核对阶段CLI的真实参数、stdin／stdout命令与事件、错误／结束语义、取消与排队、结构化结果、用量，以及会话身份、落盘、继续／恢复和退出行为；只使用公开CLI与协议，不能用日志推断权威成功或可恢复。
- 核对宿主工具注册／调用和schema、事件顺序与异步行为、信任准入、项目指令加载、任务查询展示及可供047–049采用的注入／交互能力；区分交互TUI与RPC／非交互模式下可用的能力。
- 必需兼容修复落实到核心适配或受管源模板，同步文档及现有探针。与027–042重叠的业务修复仍由原任务承接，记录新增版本约束与证据，不重复建立另一套实现。
- 对有价值的新能力给出采用或暂缓的具体理由、替换点、所支持模式及验证成本。可在现有首版范围内完成小型适配；扩大产品范围的方案明确交接，不借SDK／RpcClient、自建鉴权或模型运行时弥补公开能力缺口。
- 为044／047–050提供版本化接口约束和必要调整，明确需追加的实际验收；尚未实施的新功能不得被计入本项已验证能力。
- 更新支持版本与能力探测约定：1.5.0必需能力缺失时给出具体诊断；旧版本兼容仅在有对应证据时声明，不顺带承诺全部历史版本可用。

## 交付与完成条件

- 在新的validation目录保存精确版本、环境、来源／更新日志范围、差异表、实际命令及结果；给出“需改且已改／无需改／有利且采用／暂缓”的明确判断和证据。
- 1.5.0下验证CLI启动与流式协议、结构化阶段结果、失败与取消、原生会话实际落盘和继续／恢复；核对工具schema正常及异常调用、信任准入、宿主公开事件和桥接加载。Git／故障场景在隔离夹具，不操作真实项目历史。
- 假客户端可覆盖协议边界，真实Pi CLI与宿主最小验证分别给证据；不能用替身、帮助文本或更新日志替代实际兼容验收。必需真实能力受阻时按规则记录根因，保留未验收项。
- 对实际采用的新能力验证业务等价及其新增收益；输出截断不冒充完整成功，等待用户不冒充Agent结束，费用估算不冒充账单，观察字段不升级为独立业务状态。
- 按修改范围运行类型检查、构建、相关回归和包检查；若改源模板，核实包内生成物。既有稳定测试证据可核对复用，051再验证最终自然语言全链路，避免将两项硬串成循环依赖。
- 更新TASKS与支持说明，把当前功能兼容结论和未来工作流的接口评估分开；整体首版就绪还需043、051及既有必需门槛。
